# v18 の改善と検証の記録（2026-11-14 夜〜11-15 朝）

作業：sasaki（Claude Code と共同）。この記録は `main` を変更しない別ブランチ `notes/overnight-2026-11-15` に置いています。
**`main` のコード・設定・重みには一切手を入れていません。** 採用する場合の手順は「5. 採用する場合の手順」にあります。

## 1. まとめ

- **v18 の描く係（refiner）の貼り戻しのしきい値を 0.5 → 0.45 に下げると、手元の PQ が +0.0051 [95% 区間 +0.0022, +0.0080] 上がった。5 組すべてで上昇。公開 LB は 0.40（v18 は 0.39）。**
- さらに採点器の採用条件を「h×m ≥ 0.22、確率の平均 ≥ 0.6」にすると +0.0015（入れ子の交差検証での公正な見積もり、5 組すべてで上昇）。公開 LB は未確認。
- 別のシステム（sasaki 側の 1024 px パイプライン）との組み合わせは 4 通り試したが、どれも v18 を上回らなかった。

## 2. 評価の仕方

- 学習用 707 枚について、v18 の各段を **v18 と同じ画像単位の 5 分割（`solarfil.data.folds`、種 0）** で、その画像を学習していない組のモデルだけで予測し直した（`scripts/team_oof.py`）。見つける係は 8 方向、描く係は 2 種類 × 回転 4 通り。
- 採点器（HistGradientBoosting の h と m）は、**5 組で学習し直して**評価した。同梱の `weights/scorer.pkl` は 707 枚すべてで学習済みなので、そのまま使うと甘い値になる。
- 採点は `solarfil.metrics` と同じ（注釈者ごとに IoU > 0.5）。最後に 0.5 画素細らせる。差は画像単位のペアのブートストラップ（5,000 回）で確かめた。
- この条件での v18 の値は **0.4500**。同梱の `scorer.pkl` をそのまま使うと 0.4574 だった。ハンドブックの 0.4609 との違いは、採点器を学習に使った画像で評価しているかどうかの差と、こちらで出力を作り直した差と考えられる（原因は未確定）。

## 3. 結果

### 3.1 採用候補：描く係のしきい値（`scripts/team_refine_sweep.py`）

| 描く係のしきい値 | PQ（採点器のしきい値 0.2） |
|---|---|
| 0.40 | 0.4465 |
| **0.45** | **0.4551** |
| 0.50（v18） | 0.4500 |
| 0.55 | 0.4354 |
| 0.60 | 0.4111 |

- 0.45 と 0.50 の差：+0.0051 [+0.0022, +0.0080]、良い確率 100%。
- 組ごと（0.50 → 0.45）：0.4430 → 0.4515、0.4657 → 0.4689、0.4575 → 0.4591、0.4478 → 0.4545、0.4372 → 0.4415（5 組すべてで上昇）。
- 「元の 30% 未満なら元の形」の 30% を 20 / 40% に変えても、ほぼ変わらない。
- 注意：0.45 にすると候補の面積の合計が約 9% 増える（形が太る）。test の正解は細めという見方もあるが、公開 LB は 0.39 → 0.40 と下がらなかった。

### 3.2 採用候補：採点器の採用条件（しきい値 0.45 の上で）

- 「h×m ≥ clf かつ 確率の平均 ≥ p_mean かつ 距離 ≤ r_max」を振った（clf 0.16〜0.24、p_mean 0 / 0.6〜0.8、r_max 0.9〜1.0）。
- 707 枚での最良は clf 0.22、p_mean 0.6（0.4573）。4 組で選んで残り 1 組で採点する公正な見積もりでは 0.4551 → **0.4566（+0.0015）**、5 組すべてで上昇。r_max は効かない。

### 3.3 効かなかったこと（v18 との差、すべて 707 枚・5 組で学習し直した採点器）

| 試したこと | v18 との差 [95% 区間] |
|---|---|
| 採点器に sasaki 側の情報（1024 px の確率、候補の木の期待得点、出力との重なり）を足す | −0.0001 [−0.0013, +0.0010] |
| 両システムの候補をまとめて、1 つの採点器で選ぶ | −0.0031 [−0.0069, +0.0008] |
| 決め打ちの投票（両方一致なら低いしきい値、片方なら高いしきい値） | −0.0019 [−0.0057, +0.0019] |
| v18 の描く係で、しきい値の木（15 段）の全候補を描き直し、入れ子から厳密に選ぶ（回転 4 通り） | −0.0105 [−0.0157, −0.0052] |

補足（`team_complement.json`）：両システムはそれぞれ相手が外した注釈を約 450 本ずつ当てている（v18 だけ 447、sasaki 側だけ 457、両方 4,640）。全部拾えれば上限 +0.023 だが、どちらの候補が当たりかを見分ける手がかりがなく、実際には上がらなかった。同じフィラメントで良い方の輪郭を選べた場合の上限は +0.011（2 つの IoU の相関 0.79）。

## 5. 採用する場合の手順（`main` で行う）

1. `solarfil/config.py`：`REFINE = dict(thr=0.45, keep_small=0.3, comp="seed")`
   （採用条件も変えるなら `SCORER = dict(clf=0.22, p_mean=0.6, r_max=0.95)`）
2. `weights/scorer.pkl` を、採用する版の `*_scorer.pkl` に差し替える。
3. `python scripts/predict.py --images <test_images> --weights weights --out check.csv` で 180 枚を作り直し、提出した CSV と一致するか確かめる（`scripts/compare_submissions.py`）。
4. README とレポートの最終設定と数字を直す。比較の表に 3.1 と 3.2 の行を足す。

注意：`*_scorer.pkl` は、こちらの PC で作り直した v18 の検証用の出力（`team_oof.py`）から学習している。コードは v18 と同じだが、研究室 PC で作った出力とは浮動小数の差がありうる。手順 3 の確認は必ず行う。
